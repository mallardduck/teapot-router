Composition

Groups, sub-routers, mounting, subdomains, and resources. Middleware itself works as it does in chi.

Groups

// Path prefix
r.Group("/api/v1", func(r *teapot.Router) {
    r.GET("/users", listUsers).Name("users.list")
})

// Path prefix and name prefix
r.NamedGroup("/{bucket}", "bucket", func(r *teapot.Router) {
    r.GET("", listObjects).Name("list")                   // "bucket.list"
    r.GET("", getBucketAcl).Name("acl").Query("acl")      // "bucket.acl"
})

// Middleware scoped to the group
r.MiddlewareGroup(func(r *teapot.Router) {
    r.GET("/data", dataHandler).Name("api.data")
}, apiKeyMiddleware)

Sub-routers

SubRouter(prefix) returns a child router that can also run on its own. Its routes show up in the parent with the prefix added.

admin := r.SubRouter("/admin")
admin.GET("/dashboard", dashHandler).Name("dashboard")
// "dashboard" is visible in both admin and r, as "/admin/dashboard"

Mounting

r.Mount("/static", http.FileServer(http.Dir("./static")))

Mounting a *teapot.Router does more. Its existing routes are copied into the parent with the prefix added. Routes added to it later also show up in the parent, because mounting links the two routers.

api := teapot.New()
api.GET("/users", listUsers).Name("users.list")

r.Mount("/api/v1", api)

api.GET("/profile", profile).Name("users.profile") // also visible in r

Names can get a prefix when mounting:

r.MountNamed("/api/v1", "v1", api)     // "users.list" becomes "v1.users.list"

r.Mount("/api/v2", api).Name("v2")     // same, with the fluent form

Naming after mounting renames the routes already propagated.

Subdomains

For APIs that address resources by subdomain (mybucket.s3.example.com) as well as by path, use the dispatch matcher with the urlbuilder helpers:

d := dispatch.New(func(b *dispatch.Builder) {
    b.When(dispatch.HostHasSubdomain("s3.example.com")).DoFunc(vhostHandler)
    b.DefaultFunc(pathHandler)
})
http.ListenAndServe(":8080", d)

// Inside a handler:
label, ok := urlbuilder.SubdomainFromHost(r.Host, "s3.example.com") // "mybucket", true

Inside a teapot router, use m.HostHasSubdomain(...) in a Dispatch block. Ports are ignored, matching is case-insensitive, and a trailing dot on either side is ignored.

Resources

A resource is a controller value. Each standard action is registered only if the controller has that method.

type PhotoController struct{ db *sql.DB }

func (c *PhotoController) Index(w http.ResponseWriter, r *http.Request)   { /* list */ }
func (c *PhotoController) Show(w http.ResponseWriter, r *http.Request)    { /* one */ }
func (c *PhotoController) Update(w http.ResponseWriter, r *http.Request)  { /* PUT and PATCH */ }
func (c *PhotoController) Destroy(w http.ResponseWriter, r *http.Request) { /* DELETE */ }

r.Resource("photos", &PhotoController{db: db})
ActionMethod and pathRoute name
IndexGET /photosphotos.index
CreateGET /photos/createphotos.create
StorePOST /photos (StoreVerb can change it)photos.store
ShowGET /photos/{photo}photos.show
EditGET /photos/{photo}/editphotos.edit
HeadHEAD /photos/{photo}photos.head
ReplacePUT /photos/{photo}photos.replace
PatchPATCH /photos/{photo}photos.patch
UpdatePUT and PATCH /photos/{photo}, for any verb not covered by Replace or Patchphotos.update
DestroyDELETE /photos/{photo}photos.destroy

Update verbs in one of two ways. Implement Update to handle PUT and PATCH the same way. Or implement Replace (a full replacement) and Patch (a partial update) to tell them apart. Implementing only one of them registers only that verb. Head is optional: without it, HEAD requests fall back to the GET route.

Options:

r.Resource("photos", &PhotoController{db: db},
    teapot.Only("index", "show"),                       // or teapot.Except("destroy")
    teapot.Middleware(authMiddleware),                  // this resource only
    teapot.Path("/pictures"),                           // replaces /photos
    teapot.Param("pictureId"),                          // replaces {photo}
    teapot.Names(map[string]string{"index": "list"}),   // photos.list
    teapot.StoreVerb(teapot.PUT),                       // Store uses PUT
)

Resource panics at registration for invalid input: an unknown action, Only combined with Except, a Path without a leading slash, or a StoreVerb other than POST or PUT.

Middleware

Use chi middleware as you would in chi:

r.Use(middleware.Logger, middleware.Recoverer)

r.GET("/admin", adminHandler).Name("admin").With(authMiddleware)

The underlying chi router is available through r.Chi() when you need chi features directly.
