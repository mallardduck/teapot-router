Routing

Named routes, query and header dispatch, and S3 action context. For path patterns and middleware, see the chi docs.

Named routes

Name a route with .Name(), then build its path later with URL or MustURL.

r.GET("/users/{id}", showUser).Name("users.show")

path := r.MustURL("users.show", "id", "42")       // "/users/42"
path, err := r.URL("users.show", "id", "42")      // error-returning form

Parameters are alternating key and value pairs, and each key must match a placeholder in the pattern. Wildcards written as {key:.*} match slashes and are substituted the same way:

r.GET("/{bucket}/{key:.*}", getObject).Name("object.get")

r.MustURL("object.get", "bucket", "photos", "key", "2024/vacation.jpg")
// "/photos/2024/vacation.jpg"

URL returns an error when the name is unknown, when the pairs are odd in count, or when a placeholder is left unfilled.

Query dispatch

Routes on the same method and path can differ by query parameters. This is how S3 sub-resources such as ?acl work.

r.GET("/{bucket}", listObjects).Name("bucket.list").Action("s3:ListBucket")

r.GET("/{bucket}", getBucketAcl).Name("bucket.acl").
    Action("s3:GetBucketAcl").
    Query("acl") // matches when ?acl is present

r.GET("/{bucket}", getVersioning).Name("bucket.versioning").
    Action("s3:GetBucketVersioning").
    QueryValue("type", "full") // matches when ?type=full

More specific matches win, so a route that requires two query parameters beats one that requires one.

Grouped with Dispatch

When one path has many variants, Dispatch keeps them in one block:

r.Dispatch("GET", "/{bucket}", func(d *teapot.DispatchBuilder, m teapot.Matchers) {
    d.DefaultFunc(listObjects).Name("bucket.list").Action("s3:ListBucket")
    d.When(m.QueryEquals("list-type", "2")).DoFunc(listObjectsV2).Name("bucket.list-v2")
    d.When(m.QueryExists("acl")).DoFunc(getBucketAcl).Name("bucket.acl")
    d.When(m.QueryExists("versioning")).DoFunc(getVersioning).Name("bucket.versioning")
})
  • Default / DefaultFunc: the fallback when no When matches.
  • When(...): a conditional route. Multiple matchers are ANDed.
  • Do / DoFunc: the handler for a When route. Takes an http.Handler or a function.
  • .Name(), .Action(), .With(): the same chain as the fluent API.

Built-in matchers on teapot.Matchers:

MatcherMatches when
QueryExists(key)the query parameter is present, any value
QueryEquals(key, value)the query parameter equals the value
HeaderExists(key)the header is present and non-empty
HeaderEquals(key, value)the header equals the value
HostHasSubdomain(domain)the Host is a subdomain of domain (see Composition)

The fluent Query style and Dispatch coexist in the same router. Use whichever reads better for each path.

Action context

Each route can carry an action string, which is stored in the request context:

r.GET("/{bucket}/{key:.*}", getObject).
    Name("object.get").
    Action("s3:GetObject")

func getObject(w http.ResponseWriter, r *http.Request) {
    action := teapot.GetAction(r)           // "s3:GetObject"
    name := teapot.GetRouteName(r)          // "object.get"
    bucket := teapot.URLParam(r, "bucket")
    key := teapot.URLParam(r, "key")
    // Use action for authorization, logging, metrics...
}

URLParams(r) returns all URL parameters as a map.

Direct handlers and external routes

r.Handle("GET", "/health", healthHandler).Name("health")
r.HandleFunc("GET", "/ping", pingFunc).Name("ping")

// Documented and usable for URL building, but not served locally
r.RegisterExternal("GET", "https://auth.example.com/login", "auth.login", "auth:Login")

Finalize for production

Call Finalize() after registering routes. It precomputes handler chains and builds all dispatchers up front, so the first request does no setup. It is optional.

r.Finalize()
http.ListenAndServe(":8080", r)
